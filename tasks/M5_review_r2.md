## 最终结论（交用户审批）

数据集数量达标，但 F1（每条示范起步猛冲）、F2（恢复与动作精度不等价）影响数据质量，**修改后整体重新生成数据集**。修改清单：

1. **F1 起步与峰值判据**（`data/retarget.py`）
   - 接近段从 home 边界开始（首样本就是 home），用五次时间律；位置与姿态都从 home 出发。
   - 峰值判据：从 home 关节角出发，把最终要执行的整条动作序列（含提前一拍、末拍重复）送入 `simulate_stream(..., scheme="preview")`，IK 种子与失败回退与控制器一致；要求参考速度峰值严格 ≤ 0.5·v_max、速度超限标记全 0；同时报告未限幅时的参考峰值。
   - 统计分开报告：参考速度峰值比、闭环速度峰值比（逐物理步记录的最大值，不用 20 Hz 采样代替）。闭环峰值比 > 0.6 的示范逐条说明原因（诊断线，不是硬门槛）。
2. **F2 恢复与精度**（`sim/env.py`、`scripts/m5_generate.py`、`data/dataset.py`）
   - `capture_state` 保存并恢复 `qacc_warmstart` 和 `time`（以及其他确有需要的字段）；控制器状态与生成路径一致。
   - **从第一次闭环起就执行存储精度的动作**（例如先把动作转成 float32 再执行），或另存 float64 动作并用于回放；二选一并写明。
   - 生成改为一次执行同时记录图像，使“成功”与“写入数据集”是同一次执行。
   - 末拍 `next_action` 规则在生成、存储、回放中一致。
   - 测试：同一初始状态与同一存储动作，生成执行与回放执行的整条关节轨迹（float64 仿真状态）最大差 **= 0**；与 float32 观测的比较只要求在量化容差内。
   - 交付中如实报告 r1 的 9/122 翻转及原因；不要求“敏感比例”统计。
3. **F3 失败分类与诊断**
   - 判据改为逐物理步记录接触（或按明确的物理时长），`lost` 与 M4 一致为连续 ≥ 10 物理步（20 ms）；核对 `grasp_z` 的取法。
   - 新增类别并排在 `outside` 之前：`not_lifted`（闭合后 Can 最大抬升 < 2 cm，参考高度与时间窗写进配置）、`dropped_after_lift`（抬起过再失去双指接触或高度跌落）。按过程判定，不只看最终位置。
   - 诊断：失败与成功示范的抓取几何（本项目手指闭合方向、垂直方向、高度上的 Can–TCP 偏移；原示范的 eef–Can 偏移与工具朝向）给出分布与重叠；`ik_unreachable` 给出发生的段和位置。不设可分性门槛，不要求提高成功率。
4. **F4 段标签**
   - 每条示范逐拍存储段标签，至少区分：合成接近、人类抓取前相对位置、夹爪等待 / 斜坡 / 停留、搬运（合成基线 + 人类残差）、合成放置下降、合成撤离；标签与最终存储动作逐拍对齐。README 写明。
   - 统计“含人类位置 / 残差信息的拍数比例”分布，并给出各段时长分布；注明姿态与夹爪时序经过重写。
   - 交付与 README 中称为“部分重定向 + 合成放置”。
5. **F5 元数据**：根属性增加 `git_dirty`，以及生成依赖文件的 sha256 清单（`src/aloha_pp/data/`、`planning/noise.py`、`sim/env.py`、`scripts/m5_generate.py`、`scripts/m4_run.py`、M1 / M3 / M4 / M5 配置）。
6. **F6 长度构成**：按最终离散序列给出各段时长分解（等待和夹爪斜坡已随缩放放大）。
7. **N1**：事件索引随 prepend、重采样、提前一拍一起映射（或改名为“变换前索引”并不再使用）；F3 / F4 用最终序列上的事件位置。
