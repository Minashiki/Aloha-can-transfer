## 问题

### F1（高）每条示范开头都有一次超出“0.5 倍速度上限”的猛冲，时间缩放没有覆盖它

我读 `outputs/m5/dataset/demos.hdf5` 的 `obs/qvel`：**113 条示范的最大关节速度都出现在第 1 拍、waist 关节，等于 2.06 rad/s（速度上限的 1.03 倍）**，同一拍 wrist_rotate 为 3.00 rad/s（上限的 1.00 倍）。以 demo_0025 为例：

- 初始 TCP (0.279, 0.000, 0.186)，第 0 个动作已是 (0.271, 0.041, 0.185)，一个控制周期跳了 4.2 cm（0.84 m/s）；
- q 在 0.5 s 内 waist 从 0 到 0.58 rad。

原因：交付第 5 节第 9 条，“从 home TCP 先有 0.5 s 直线接近，再对整条轨迹做 IK，按关节差分峰值放大时间”。这 0.5 s 接近段是固定时长、匀速直线（第一拍就是满步长），而峰值检查只看 20 Hz 结点之间的有限差分，没有包含 home → 第一个结点这一步，也没有包含五次插值段内部的峰值。参考流在这一拍被速度上限截断，闭环速度超过上限。交付里“闭环 `qvel` 峰值约为速度上限的 1.03 倍”就是这一处，但被解释成“跟踪控制器的实际速度”，没有找到原因。

影响：所有示范开头都是一次被限幅的猛冲，违反 dispatch 第 2.8 条（峰值不超过 0.5·v_max）；M6 的扩散策略会学到这个起步动作。

**要求**：
1. 接近段用平滑时间律（与 M4 相同的五次时间律），纳入时间缩放。
2. 峰值判据改为用实际参考流计算：从 home 关节角出发，用 `simulate_stream(..., scheme="preview")`（M4 规划器的做法）对整条动作序列求关节参考速度峰值，要求 ≤ 0.5·v_max（严格，不再出现 0.5002）且速度超限标记全为 0。
3. 统计中给出每条示范闭环 `qvel` 峰值 / 上限的分布，以及出现位置；任何一条超过 0.6 都要说明原因。

### F2（中）重放 / 二次执行不是逐位一致，导致 9 条成功示范被丢弃

交付说 122 条无渲染成功中有 9 条在写图像的第二次执行中失败，“接触在两次执行之间有发散”；抽样重放的关节偏差最大 5.5e-4 rad。

我用 M4 规划器（random，seed 3，medium）做了对照：

| 对照 | 关节轨迹最大差 |
|---|---|
| 两次正常 `reset(seed=3)` 后执行同一动作序列 | **0.0** |
| 正常 reset vs `reset(state=capture_state())` | 4.9e-5 rad |
| 再额外恢复 `qacc_warmstart` 和 `time` | 7.0e-5 rad（仍不一致） |

逐字段比较 reset 之后的状态：`qpos`、`qvel`、`ctrl`、`qacc_warmstart` 都相同，但**控制器的 `home_q` / 参考流初值差 2.2e-12**。原因：正常 reset 在 50 步沉降**之前**调用 `controller.reset`（`home_q` 取沉降前的 q），`_reset_from_state` 在恢复状态**之后**调用（取沉降后的 q）。`qacc` 也有 2e-9 的差。仿真本身是确定的；差别来自恢复路径不等价，接触把 1e-12 级的差放大到 1e-4，部分临界示范因此翻转。

**要求**：
1. 让 `capture_state` / `_reset_from_state` 与正常 reset 逐位等价（至少包括控制器的 `home_q` 和参考流初值、`qacc_warmstart`、`time`，其他需要的字段自查）。测试：同一动作序列，正常 reset 与状态恢复后的关节轨迹最大差 **= 0**（整条 episode）。
2. 数据生成改为一次执行同时记录图像（或保证二次执行逐位一致），使“无渲染成功”与“写入数据集”的集合相同。
3. 统计中报告：有多少示范对 1e-12 级扰动敏感（例如对比原 r1 的两次执行结果），作为数据集“临界示范”比例写进报告素材；不要求剔除。

### F3（中）43 条“outside”失败的分类不可信

`outputs/m5/episodes.csv` 中 43 条 `outside` 失败的最终 `place_xy` 在 **0.153–0.240 m**，成功示范是 0.6–22.9 mm。左 bin 中心到目标格中心约 0.21 m，所以这些 Can 基本没有离开左 bin，不是“放到格外”。

原因（`scripts/m5_generate.py:109–143`）：`grasped` 只要求闭合指令期间出现过一次双指接触；`dropped` 要求 Can 高于格心 2 cm 时双指都不接触，或低于抓取高度 `drop_z`。Can 被夹到但没被提起来（滑脱、夹偏）时两个条件都不满足，于是落到 `outside`。另外这里的 `lost` 用 `np.any`（单步即算），与 M4 N1 定下的“连续 ≥ 10 步”不一致。

**要求**：
1. 增加“未提起”类（例如闭合期间 Can 最大抬升 < 2 cm，阈值写进配置），放在 `outside` 之前；`lost` 改为与 M4 一致的连续 ≥ 10 步。
2. 对“未提起 / 掉落”类做原因诊断：比较失败与成功示范的抓取时 Can–TCP 偏移（沿手指闭合方向、垂直方向、高度），以及原示范抓取时的 eef–Can 偏移；给出能区分两者的量。不要求提高成功率，但要知道为什么失败。
3. `ik_unreachable` 32 条给出不可达发生在哪一段（接近 / 抓取前 / 搬运 / 放置）和对应的位置。

### F4（中，说明）重定向示范中有相当一部分是合成的，需要量化并写进数据集

交付第 5 节：抓取前的轨迹来自人类示范（Can 坐标系平移）；搬运段只保留残差；**放置段被替换为“平移到格子正上方 → 下降到格心 + 偏移 + 6 mm → 张开 → 上抬 8 cm”**（人类示范在 0.24 m 高处松手，本项目格子太小）；姿态全程改为 `choose_yaw`（人类 yaw 不保留）；另外插入了 home 接近段和开合等待。

2. 统计中给出每条示范“来自人类数据的拍数占比”的分布。
3. 交付记录明确写出这是“部分重定向 + 合成放置”，不要只写“重定向”。
