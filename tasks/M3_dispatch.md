## 要做的事

### 1. 底层控制接口（`src/aloha_pp/control/`，并扩展 `sim/`）

- 扩展接口，使控制器可以**在每个物理步**计算力矩：每个 20 Hz 动作调用一次 `set_target(...)`，每个物理步调用一次 `compute(...)`（命名自定）。M1 的 `PositionIkController` 必须继续可用，行为不变。
- 每个物理步计算 τ 时，所用的 q、q̇、`qfrc_bias`、`qM` 必须与当前状态一致。写明实现方式，并用测试证明（参考交接单第 5 节）。
- 只对 6 个臂关节施加力矩；夹爪仍用 position 执行器。所有控制器的输出都按 `actuatorfrcrange` 限幅，并在每个物理步记录各关节是否饱和。

### 2. 参考轨迹与插值（`src/aloha_pp/control/` 或 `planning/`）

- **20 Hz → 500 Hz 管线**（PLAN 第 2 节）：每收到一个 20 Hz 的笛卡尔目标，就用 DLS IK 求一次（以上一个解为初值）。在相邻两个关节目标之间，做关节空间多项式插值，得到每个物理步的 q_d、q̇_d、q̈_d。
  - q_d 和 q̇_d 必须连续（至少 C¹），q̈_d 必须有界。
  - 写明插值方法、每个段端点的速度怎么取，以及由此带来的滞后。
- **速度限制**（`configs/` 中的 `velocity_limit`）：
  - 离线生成参考轨迹时，如果超过速度上限，就拉长时长；
  - 在线插值时，如果某一段需要的速度超过上限，就按上限限幅，并记录“速度超限”标记。速度超限占比要写进统计。
- **IK 容差**：比较 1e-3 m / 1e-2 rad 和 1e-4 m / 1e-3 rad 两组，给出收敛率、单次求解耗时（中位数和最大值）、残差，然后选定一组写进配置，并说明理由（PLAN M3 的要求）。IK 残差要单独记录，不能混进跟踪误差。
- **实验参考轨迹**：对 `fixed_1` 和 `fixed_2` 分别生成笛卡尔路点序列 home → 抓取预备位（Can 正上方）→ 下降到抓取高度 → 抬起 → 放置格正上方 → 下降到放置高度 → 抬起 → home。姿态都是从上往下，不带夹爪动作，M3 只做跟踪，不抓 Can。段与段之间用平滑时间律（例如五次多项式），按 20 Hz 采样后送进上面的管线。
- **三档速度**：
  - fast：轨迹最短总时长，按速度上限确定，峰值关节速度接近但不超过上限；
  - medium：fast 时长 × 2；
  - slow：fast 时长 × 4。
  - 写出每档的实际总时长和峰值关节速度。

### 3. 控制器

| 编号 | 实现 | 模型 |
|---|---|---|
| B0 | MuJoCo 内置 position 执行器（Menagerie kp、kv），没有重力补偿；直接接收插值后的 q_d | position 版 |
| B1 | B0 + `apply_gravity_compensation(True)` | position 版 |
| C1 | `τ = Kp·e + Kd·ė` | motor 版 |
| C2 | C1 + g(q)，g 来自 MuJoCo，即速度为 0 时的 `qfrc_bias` 或者等价的计算方式 | motor 版 |
| C3（主控制器） | `τ = M(q)·q̈_d + Kp·e + Kd·ė + g(q) + C(q,q̇)q̇ + B·q̇_d`，M 来自 `mj_fullM`，`g + C q̇` 来自 `qfrc_bias` | motor 版 |
| C4 | C2 + 积分项（带抗饱和，方法自选并写明） | motor 版 |

- **增益**：C1–C4 使用**同一套** Kp、Kd，这样各控制器之间的差别只来自前馈 / 积分项。增益的设计依据要写明，例如按 M 的对角线和目标带宽 ω 取 `Kp = M_ii·ω²`、`Kd = 2ζ·M_ii·ω`。增益写在配置文件里。
- **C2 与 B1 的一致性**：另外跑一组 C2，用 Menagerie 的 kp / kv 作为 Kp / Kd，和 B1 比较（PLAN 要求“C2 应接近 B1”），给出两者跟踪误差的差别和原因分析。
- **C4 接触实验**（说明为什么不用积分项）：设计一个接触场景，例如命令 TCP 压到 bin 底板以下 1 cm 并保持 2 s，然后抬起。对比 C2 和 C4 的积分状态、力矩饱和情况，以及抬起时的超调。
- O1（OSC）不做。

- 用配置文件枚举 {B0, B1, C1, C2, C3, C4} × {fixed_1, fixed_2} × {fast, medium, slow}，共 36 组，再加上第 3 节中的两组附加实验。
- **统一日志**：每组实验一个文件（npz 加一个 json 元数据），保存在 `outputs/m3/runs/`。逐物理步记录：t、q、q̇、q_d、q̇_d、q̈_d、τ（命令值和实际施加值）、饱和标记、速度超限标记、TCP 实际位姿、TCP 参考位姿（原始参考轨迹）、IK 残差。元数据包括控制器、增益、模式、速度档、总时长、git commit。
- 实验时**不渲染**相机图像；另外为 C3 和 B0 在 `fixed_1` 的 fast 档各录一段小视频（≤ 2 MB）。

### 5. 统计与绘图（`scripts/m3_analyze.py`，**只读日志**）

- 汇总表（CSV 和 Markdown），每组一行：
  - 关节跟踪 RMSE / 最大误差（q − q_d）；
  - TCP 误差 RMSE / 最大值，分两种：相对原始参考轨迹，以及相对 FK(q_d)；
  - 稳态误差：轨迹结束后静止 0.5 s 期间的平均误差；
  - 力矩饱和占比、速度超限占比、峰值力矩 / 力矩上限。
- 曲线：
  - 典型组（`fixed_1` fast）各控制器的关节误差和力矩曲线；
  - 各控制器的 RMSE 随速度档变化的对比图；
  - B0 的重力下垂；
  - C2 与 B1 的对比；
  - C4 接触实验。
- 用 3–6 条结论回答两个问题：
  1. 各控制器在不同速度下的差异，以及原因（前馈、重力补偿、饱和）。
  2. “在策略动作频率和幅度范围内，底层能否跟住”（PLAN 第 6 节）：以 C3 在 fast 档的误差作为依据。
